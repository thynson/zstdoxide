# Official golden corpus port

## Design and ownership

The source is facebook/zstd v1.5.7, commit
`f8745da6ff1ad1e7bab384bd1f9d742439278e99`. The four `tests/golden-*`
directories provide immutable byte fixtures. Each fixture is borrowed as an
`&'static [u8]`; Rust decoder and encoder results are owned `Vec<u8>` values.
Fixture names and relative paths identify cases; no pointers or unsafe test
infrastructure are needed. Output sizes are explicit resource limits.

The port preserves original bytes, filenames, and per-file SHA-256 checksums.
The importer reads an external upstream checkout and the official v1.5.7 CLI
only as an oracle. Reference C source is not copied into this repository.
Upstream fixture copyright is Meta Platforms, Inc. and affiliates; the retained
BSD license is `LICENSE.zstd` at the repository root.

## Test correspondence

`tests/upstream_golden.rs` ports `tests/playTests.sh`'s decompression-only
checks and its `golden files tests` section. It decodes every successful
golden frame and rejects every golden decompression-error frame. Expected
outputs are generated by the official CLI and committed for offline testing.
Large uniform expected outputs are described by their verified byte and length
instead of storing redundant megabytes.

Every original golden compression input is encoded by Rust and decoded
back to the original bytes. Separately, committed frames generated from those
inputs by the official CLI are decoded by Rust. An explicitly invoked
oracle test decodes Rust frames with the official executable. Compressed
byte identity is not required: different valid encoders need not choose the
same parse, entropy tables, or block boundaries.

The dictionary asset is retained, with an official dictionary-compressed frame.
Until the Rust dictionary API exists, the supported API is tested to
reject that frame with `DictionaryRequired`. The upstream dictionary
round-trip remains explicitly blocked; rejection does not count as that test
passing.

## Reproduction

The importer and generated manifest document precise generation commands,
expected output metadata, and all source and derived checksums. Normal Cargo
tests require neither an upstream checkout nor a C compiler nor a zstd binary.


```sh
python3 scripts/import_upstream_golden.py /path/to/zstd-v1.5.7
python3 scripts/import_upstream_golden.py /path/to/zstd-v1.5.7 --check
cargo test --test upstream_golden
ZSTD_BIN=/path/to/zstd cargo test --test upstream_golden -- --ignored
```

The importer requires an unchanged checkout at the pinned revision and a
v1.5.7 executable. `--check` recomputes derived frames and verifies every byte
and all SHA-256 metadata without modifying files. The manifest contains twelve
original assets and five generated frames. Original dotfile metadata is not a
test fixture and is excluded.

| `golden-compression` | `huffman-compressed-larger` | Rust round-trip, official-frame decode, output limit, CLI interoperability |
| `golden-compression` | `http` | Rust round-trip, official-frame decode, output limit, CLI interoperability |
| `golden-compression` | `large-literal-and-match-lengths` | Rust round-trip, official-frame decode, output limit, CLI interoperability |
| `golden-dictionaries` | `http-dict-missing-symbols` | Asset and oracle frame preserved; dictionary-required rejection; upstream round-trip blocked |

There are twenty regular tests and one opt-in CLI interoperability test. The
CLI test covers all four compression inputs and feeds and drains its subprocess
concurrently to avoid pipe deadlocks. It is ignored by default only because it
requires an external executable. The upstream dictionary round-trip is not
represented by an empty ignored test: a working port requires dictionary APIs
that the crate does not yet expose.

The default-level Rust compression test is an adaptation of the upstream
encoder test. It preserves the source corpus and byte-equality round-trip
contract, but does not exercise upstream-specific block splitting, compression
levels, or strategies that the Rust encoder does not implement.
