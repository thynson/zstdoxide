# Official golden corpus port

## Design and ownership

The source is facebook/zstd v1.5.7, commit
`f8745da6ff1ad1e7bab384bd1f9d742439278e99`. The four `tests/golden-*`
directories provide immutable byte fixtures. Each fixture is borrowed as an
`&'static [u8]`; Rust decoder and encoder results are owned `Vec<u8>` values.
Fixture names and relative paths identify cases; no pointers or unsafe test
infrastructure are needed. Output sizes are explicit resource limits.

The port preserves original bytes, filenames, and per-file SHA-256 checksums.
The importer reads an external upstream checkout and the official v1.5.7 CLI
only as an oracle. Reference C source is not copied into this repository.
Upstream fixture copyright is Meta Platforms, Inc. and affiliates; the retained
BSD license is `LICENSE.zstd` at the repository root.

## Test correspondence

`tests/upstream_golden.rs` will port `tests/playTests.sh`'s decompression-only
checks and its `golden files tests` section. It will decode every successful
golden frame and reject every golden decompression-error frame. Expected
outputs are generated by the official CLI and committed for offline testing.
Large uniform expected outputs are described by their verified byte and length
instead of storing redundant megabytes.

Every original golden compression input will be encoded by Rust and decoded
back to the original bytes. Separately, committed frames generated from those
inputs by the official CLI will be decoded by Rust. An explicitly invoked
oracle test will decode Rust frames with the official executable. Compressed
byte identity is not required: different valid encoders need not choose the
same parse, entropy tables, or block boundaries.

The dictionary asset is retained, with an official dictionary-compressed frame.
Until the Rust dictionary API exists, the supported API will be tested to
reject that frame with `DictionaryRequired`. The upstream dictionary
round-trip remains explicitly blocked; rejection does not count as that test
passing.

## Reproduction

The importer and generated manifest will document precise generation commands,
expected output metadata, and all source and derived checksums. Normal Cargo
tests require neither an upstream checkout nor a C compiler nor a zstd binary.
