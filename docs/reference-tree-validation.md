# Bounded reference BinaryTreeLazy2 preparation

BinaryTreeLazy2 remains unsupported. Module 15 production inputs are frozen
while its correctness and timing closure runs. This document records additive
preparation only; it does not change the scope of that immutable matrix.

## Permanent predecessor baseline

The [baseline evidence](evidence/2026-10-13-lazy-baseline.json) preserves 80
Lazy/Lazy2/Greedy/DoubleFast/Fast cases from the completed sixteen-configuration
clock-free campaign. Its 36 distinct complete frames occupy 22,819,999 bytes.
The separate offline checker reconstructs every frame and allocator record
from the pinned archive, without importing a codec or executing archived code.
Two Python modes each accept the original/restored fixture and reject 15
mutations with no child processes.

The new `reference_lazy_defaults` target passes all 21 tests separately in safe,
unsafe-reference-chain, unsafe-row-table and all-feature builds: 84 executions.
It checks deterministic source fingerprints, resolved tuples, complete frame
bytes, standard frame extents, decoder reconstruction, exact qualified allocator
records, unchanged request/source and final owner release. Exact layout/byte
accounting is qualified to the recorded aarch64 macOS compiler; other targets
still enforce output and owner/category invariants. Focused safe/all Clippy and
formatting pass. These additive tests were created after the Module 15 matrix
snapshot and are not retroactively counted in it. Earlier baselines are intact.

## Input-only direct search preparation

Thirty deterministic recipes contain 13,888 source bytes. They vary tiny/inclusive
tails, effective minimum matches, unsorted-chain budgets, paired-ring boundaries,
lexical byte order, window floors, hash dimensions and the 256-operation cap.
Names express intended coverage; no actual C branch witness is claimed before
capture. The [input evidence](evidence/2026-10-13-tree-inputs.json) preserves the
exact recipes, request transport, contract and controls.

Both Python modes verify every canonical packet round trip, accept maximum-size
and inclusive-tail positive controls, and reject 61 malformed scalar, source,
schedule, packet and manifest cases. Duplicate/non-finite JSON and bool/float
integer substitutions are rejected. A process audit hook records no attempted
child execution. All archive members were read back and compared. No production
codec or C helper has been added by this checkpoint.

## Helper and observation-reader preflight

The [helper review](evidence/2026-10-13-tree-helper-review.json) checks normal and
ASan/UBSan syntax with warnings denied and binds all 22 actual include dependencies
to the pinned reference source. No C executable was run at this checkpoint.
The separate [reader evidence](evidence/2026-10-13-tree-validator.json) records
two synthetic positive controls and 56 rejected mutations in each Python mode,
with no attempted child processes. Selected-byte replay, skipped-query immutability,
complete map continuity, raw node/window floors, exact owner accounting and
padding-independent records have independent checks.

The reader holds one bounded JSON record at a time plus previous maps and compact
first-pass fingerprints; stdout and line extents are capped before parsing.
It checks hash-head/source association, but does not recreate deferred sorting or
predict the best candidate. Plausible alternative maps require binding to immutable
captured bytes, not an unsupported claim that structural replay proves unique tree
semantics. The synthetic records are not reference observations or Rust expectations.
