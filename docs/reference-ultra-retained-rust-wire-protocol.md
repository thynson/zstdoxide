# Private retained Ultra Rust wire qualification

This additive protocol observes the 18 automatic-literal policy-2 recipes from
`oracles/ultra_retained_recipes.py`. Earlier recipes, models and captures remain
immutable. Disabled-literal fixtures remain private parser controls. Source,
geometry and copied schedules are inputs; the actual Rust frame's block kinds
drive independent policy-2 replay. Native block-kind hypotheses are retained only
for comparison and never determine Rust publication.

The test-only frame observer emits one source and one complete frame per recipe,
plus `observations.json`, into a fresh directory using create-new file operations.
These 37 regular artifacts are the complete capture inventory. Bounded JSON
records carry absolute block coordinates, kinds, incoming/candidate/committed
repeats, literal bytes, tail length and offset-intent sequences. Published token
access remains test-only; production callers cannot observe partial tokens.

The independent auditor checks exact source recipes, ordered case inventory,
source-aware frame headers, contiguous block extents, final flags, raw/RLE payloads
and complete exhaustion. It derives every literal, sequence, tail and repeat
transition from source under the observed wire kinds using the frozen independent
retained policy model. It does not decode compressed payloads. Complete Rust and
pinned v1.5.7 CLI decoding are separate checks, retaining each exact command,
executable identity, output bytes and source/frame hashes. Decoded outputs and
qualification logs live outside the strict 37-file capture directories.

Read-only controls run in ordinary and optimized Python with child execution
blocked. They reject effective canonical JSON forgeries in both the first and
second blocks, including boolean/integer substitutions, literal/sequence/offset
changes, all repeat owners, block coordinates, kinds and tails. Case inventory,
truncated/changed/trailing source or frame bytes, and unexpected artifacts are
also rejected. The planned inventory is 34 negative controls and two positive
audits per interpreter mode. Every mutation must differ from the baseline in
canonical JSON or file bytes; restoring it must reproduce the baseline report.

Before capture/native execution, record the complete Rust and model/recipe source
closure, protocol, capture test, controllers and pinned decoder identity. Safe/all
captures must match exactly, including token histories and complete frame bytes.
Preserve failed commands and their exact sources; use additive successor helpers
for corrections. These are private frame checks. Public request resolution,
retained Ultra2, dictionaries and complete upstream parity remain separate.

The native decoder is the exact previously qualified Homebrew v1.5.7 CLI,
SHA-256 `d36baef4919b567feff3973ef2edc07e0373b8015495f0248b80e3646d383cee`.
The controller copies this executable and its `@loader_path/../lib` Zstandard
library before execution. Their original/copy hashes, resolved paths and sizes
are checked before and after. The absolute xz/lz4 load dependencies are also
pinned and copied as provenance; the CLI still loads those absolute paths.
System-library dependencies are recorded through `otool -L`. Native decoding
uses `-d -q -c -M1M`; every output must equal its independently generated source.
The planned controller inventory is 45 commands: four dependency inventories,
one version check, two Rust captures, 36 native decodes and two independently
controlled Python audits. The complete source/controller/native inventories are
saved before the first executable or native-decoding invocation.
