# Retained Ultra2 native observer adaptation review

This helper remains an oracle only. It embeds the pinned v1.5.7 parser through
`ultra2_instrumentation.instrument`; removing its nineteen read-only hooks must
recover the entire original `zstd_opt.c` byte-for-byte. No provider, match list,
price, branch condition, reset statement or source length is replaced.

The frame/coordinator scaffold is derived from `ultra_retained.c`. Twenty-three
recorded adaptations must reverse exactly to that file. The lifecycle observer
functions derive from `ultra2.c`; both donor sources and all dependency modules
belong to the captured source inventory. The additions are:

- Explicit block/phase tags and first-block eligibility, pass begin/end and reset
  observations, preserving canonical sparse path/search baselines across phases.
- The actual Ultra2 strategy and wrapper. Only bootstrap-enabled policy 2 and
  two-to-four-block packets enter this native helper. Model-only fresh/disabled
  controls never become fake sequence-store contents in a complete frame.
- A 32768-byte guarded prefix within the source allocation. Subtracting at most
  an 8192-byte first block from the native base stays inside the allocation.
  Source anchors remain physical frame offsets; lifecycle origins and search
  cells retain native bias. Prefix/tail/allocator guards remain checked.
- Seven-byte minimum blocks, 8192-byte maximum blocks and 32768-byte frame source.
  The packet cap is exactly 68+32768 bytes. All fields and the complete schedule
  are validated before observation output or codec allocation.
- Existing ordinary Begin/Continue/End publication, pending/committed repeat
  owners, full frame decode and allocation ledger recording. Discarded sequences
  are reset by upstream, and the observer verifies that reset before clearing
  its own observation count. Learned tables and physical search cells survive.
- Event counts are accumulated per algorithm pass, including the discarded
  first pass, rather than counting only the last pass of each actual block.

Before executing any helper, pure preflight must verify the exact command plan,
all compiled units and transitive local source identities, the original pinned
reference hashes, unique reversible instrumentation and helper edits, sanitizer
flags and environment, bounded logs/frames/ledgers, strict malformed diagnostics,
and no child execution during preflight. Both normal and ASan/UBSan builds keep
upstream workspace redzones and compile the helper with strict warnings.

Independent replay covers every phase and actual publication using the source
model. Copied-evidence controls change both native builds identically and repair
all corresponding hashes, so cross-build equality cannot substitute for semantic
validation. New controls include first-only eligibility, discarded-token counts,
caller/candidate repeats, rebase coordinates, later entry frontiers, phase counts
and coherent table/sum and origin mutations. Actual frame kinds must also match
predeclared hypotheses and the complete wire structure. These checks do not
claim public Rust admission or successor foreign-platform qualification.

The first adapter generator stopped on an ambiguous declaration/definition
anchor before producing C. Subsequent source review corrected a generated JSON
key and aligned the packet array cap before any C compilation or execution.
All generator sources, the failure receipt and earlier unexecuted drafts are
retained separately. They are not successful native runs.

Source review of `ZSTD_minLiteralsToCompress` and the zero-sequence literal
path corrected the initial raw hypotheses for uniform first blocks of eight
and nine bytes to compressed blocks before any native execution. Thirty other
predictions are inherited unchanged; the two corrected cases are replayed.
The original hypotheses and their successful source-model checks remain
separate evidence, without claiming they were observed native decisions.
