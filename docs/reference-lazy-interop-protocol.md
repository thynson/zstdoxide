# Bounded Lazy-family public interoperability

This successor is specified before public C execution. It preserves every
Greedy-era public recipe and historical result, then adds Lazy/Lazy2 source-only
requests under the frozen v4 admission mapping. Reference: facebook/zstd v1.5.7
revision `f8745da6ff1ad1e7bab384bd1f9d742439278e99`.

## Inputs and ownership

Retain all 422 previous public source/request pairs and exact archived Rust
resolved tuples. Add all 340 ordinary depth-one/two sources as fresh public
one-shot requests; their prior internal schedules, table dimensions and branch
labels do not become public observations. Include all four newly admitted
original selector prefixes, every level 5 through 12 at each preset transition,
maximum supported table dimensions, hint/key/target equivalences and rejected
resource/unsupported cases. Freeze source bytes, request scalars, classifications
and complete-frame equivalence hypotheses before executing either codec.

Recipe metadata is a bounded test-only Python value. Sources and frames retain
4 MiB and 5 MiB individual caps; the new combined recipe cap is 256 MiB. This
adds no production Rust owner or unsafe backend. The manifest will record exact
counts and identities. Admission predictions use actual known-source adjustment;
C is never run for a Rust-rejected profile, and historical rejections remain
historical facts even when the new policy admits a request.

## Unchanged generic transport

Reuse the exact immutable `reference_greedy_oracle.rs`,
`reference_greedy_frames.c` and `greedy_interop_protocol.py` adapters. Despite
their historical filenames, they already accept every scalar strategy 1..9,
apply public requests and report errors without implementing a codec or
predicting admission. Their wire format has no strategy-specific layout. The
request magic remains `ZGOI0001`, with Rust/C response magic `ZGOR0001` and
`ZGOC0001`; all sizes, malformed controls and strict one-frame checks retain
the reviewed predecessor contract. No modified helper is disguised under an
old source identity. The new controller/auditor and manifest have new identities.

Rust uses the public one-shot request API and separately reports its resolved
scalar tuple. C uses a fresh context, applies level/overrides/hint, pledges the
source size, and calls `ZSTD_compress2` without dictionaries, workers or LDM.
C does not report applied scalar parameters. Independently produced entropy
bytes need not match Rust; every admitted Rust frame must decode in normal and
instrumented C, and every C frame in safe and all-feature Rust. Safe/all Rust
frames must match each other; normal/instrumented C frames must match each other.

## Execution and independent audit

Build all 26 used C translation units and the unchanged helper in normal and
ASan/UBSan modes. Validate exact pinned source/header identities, dependency
files, complete command order, binary identities, environment and successful
sanitizer silence. Assembly, worker threads and LSan remain outside this run.
Reject all 39 frozen malformed packets in both C and both Rust executables.
Use fresh external output and reference directories and preserve failed runs.

Before execution, freeze a complete source-name closure and reviewed source
identities, then qualify plan/input/output rejection with child creation blocked.
After execution, an independent reader must reconstruct every request/response,
check complete decoded bytes and frame metadata, preserve all 422 archived
scalar tuples and all predecessor source/request fields, and verify every
classification/equivalence total. Coherent changed logs/metadata must still fail
semantic or historical checks. Normal and optimized offline controls accompany
read-back archival of the complete capture. No capture result alone closes the
remaining full matrix, target interpretation, timing or upstream migration gates.
